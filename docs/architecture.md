# 架构

一台机器，四个容器。没有 k8s，也不需要。

## 拓扑

```
internet
   │ 443
   ▼
nginx ──────► app ──────► mysql
               │
               └────────► redis
```

## 端口

| 服务 | 容器内 | 宿主机 | 说明 |
| :--- | :--- | :--- | :--- |
| nginx | 80 / 443 | 80 / 443 | 唯一对外的入口 |
| app | 3000 | 不映射 | 只走 compose 内网 |
| mysql | 3306 | 不映射 | 避免被扫，需要时用 ssh 隧道 |
| redis | 6379 | 不映射 | 同上 |

## 数据落在哪

| 数据 | 位置 | 保留 |
| :--- | :--- | :--- |
| MySQL | 命名卷 `mysql-data` | 永久 |
| Redis | 命名卷 `redis-data`（appendonly） | 永久 |
| 日志 | `./logs/nginx` | 按天切分后保留 30 天 |
| 备份 | `./backup` | 7 天 |

## 为什么不用 k8s

就一台机器、四个容器。k8s 解决的问题这里一个都没有，反倒多一层要维护的东西。
compose 起停一条命令，出问题 `docker compose logs` 就能看，够了。

## 已知问题

- 证书是手动续的，还没接 certbot，每次到期前要记得去续

- 备份只落在同一块盘上，严格说不算备份
